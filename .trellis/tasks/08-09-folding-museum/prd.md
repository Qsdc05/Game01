# 折叠博物馆休闲合成游戏

## Goal

制作一款可部署到 Cloudflare 的新颖休闲合成消除游戏。玩家通过旋转展柜、折叠边界改变文物的空间邻接关系，再完成合成、连锁与每日挑战；账号、云端存档和排行榜形成可持续游玩闭环。

## Requirements

### Gameplay

- 游戏名暂定《折叠博物馆》。
- 采用 4×4 棋盘，划分为四个可独立操作的 2×2 展柜区域。
- 玩家使用点击按钮操作：先选择展柜，再点击顺时针/逆时针旋转；选择相邻展柜后可执行折叠，使边界格在本次操作中临时相邻。
- 相同等级文物形成 3 个或以上的有效组合时合成更高等级文物，并支持连锁、倍率和特殊文物效果。
- 首版包含 8 个文物等级、步数限制、分数、连锁倍率、撤销次数和关卡目标。
- 提供每日挑战和自由模式：每日挑战使用北京时间（UTC+8）每日 00:00 切换的固定地图；自由模式使用随机地图。
- 只有每日挑战成绩进入全球排行榜；每日挑战需要固定版本和可验证的初始地图。

### Accounts and access

- 未登录用户不能进入游戏主界面或开始游戏，只能看到登录/注册页面。
- 注册必须使用有效邀请码；邀请码由单一管理员后台生成、查看、作废，支持一次性使用。
- 管理员账号不开放注册，管理员用户名和密码通过 Cloudflare Secrets 配置，不提交到 GitHub。
- 用户使用用户名/密码注册和登录；密码不得明文保存，使用 Worker Web Crypto 安全哈希。
- 登录使用服务端会话 Cookie；会话具备过期机制和登出能力。

### Persistence and leaderboard

- 游戏进度统一保存到 Cloudflare D1；登录后跨设备恢复。
- 前端可使用内存状态和短暂缓存改善交互，但不把本地数据作为正式存档源。
- 排行榜按日榜、周榜、总榜展示，成绩绑定用户账号，显示昵称、分数、步数、最高文物和提交时间。
- Worker 对成绩做基础校验、重复提交处理、请求频率限制和异常分数拒绝。
- API 或网络暂时不可用时，要给出明确提示；不能导致游戏界面崩溃。

### Delivery

- 使用 GitHub 进行版本管理，项目根目录初始化 Git 仓库并提供 README、环境变量说明、数据库迁移和部署文档。
- 前端部署到 Cloudflare Pages；API 部署到 Cloudflare Workers；数据使用 Cloudflare D1。
- 不提交 Cloudflare API Token、管理员凭据或生产数据库信息。
- 页面适配桌面端和移动端，核心操作不依赖复杂拖拽手势。

## Acceptance Criteria

- [ ] 新用户没有登录时无法开始游戏。
- [ ] 有效邀请码只能成功注册一次；无效、已用或已作废邀请码会被拒绝。
- [ ] 管理员可登录后台生成和作废邀请码，普通用户不能访问管理功能。
- [ ] 用户登录后可以开始每日挑战或自由模式；刷新和换设备登录后可以恢复云端存档。
- [ ] 旋转和折叠操作能改变有效邻接关系，合成、连锁、计分和结束条件可稳定复现。
- [ ] 每日挑战在同一北京时间日期内对所有用户产生相同初始地图，并可提交成绩。
- [ ] 日榜、周榜、总榜能够读取并展示有效成绩；非法或过于频繁的提交会被拒绝。
- [ ] 前端和 Worker 可在本地运行，并有清晰的 Cloudflare Pages/Workers/D1 部署步骤。
- [ ] 关键游戏逻辑、认证、邀请码、存档和排行榜接口有自动化测试或可重复验证脚本。
- [ ] 项目能够提交到 GitHub，敏感配置不会出现在版本库中。
